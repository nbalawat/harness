# KYC Review Desk — slices

- **Slice 1 — Case intake and deterministic completeness check** (`case-intake-completeness`; REQ-001…REQ-014, REQ-055, REQ-070, REQ-089, REQ-094). A submission opens a case and runs the approved `case-intake-and-risk-scoring` workflow through `workflow_engine` — handlers `open_case_from_submission`, `run_document_completeness_check`, `mark_case_ready`, `compute_risk_score_from_matrix`, `start_sla_clock` and `return_case_with_missing_documents` are registered at import in `backend/ext_cases.py`. The package is checked mechanically against versioned Document Checklist v2.0 (`backend/kyc_policy.py`), including conditional items for deep ownership chains, regulated industries and expected cross-border activity: a complete package moves the case to `ready` with a case-ready timestamp, an incomplete one is `returned` with the itemised `missing_documents` list plus a notification to the submitter. No role may waive a required item — `POST /cases/{ref}/waive-document` always refuses with 403 and records the refusal on the trail. Cases are addressed case-insensitively by submission reference. Endpoints, all registered outside `/api/` so the `/api/{table}` catch-all cannot shadow them: `GET /checklist`, `POST /cases`, `GET /cases`, `GET /cases/{reference}`, `POST /cases/{reference}/waive-document`. Storage is `db.store` only (`cases`, `documents`, `missing_documents`, `notifications`, `audit_trail`, `risk_scores`, `sla_tracking`, `users`); every state change writes an `audit_trail` row via `ext_audit.record`. UI: a live intake form and register table added inside the design's existing `#screen-worklist`, and a live case file showing the mechanical completeness result and outstanding-item list inside `#screen-case` — both built from the Dossier design's own classes and `tokens.css` variables, `textContent` only, with `cases.js` added alongside the untouched `app.js`. One reference is one case for the life of the relationship: re-submitting an existing reference opens a new **cycle** on the same `case_id` (`cases.cycle`, checklist and missing-document rows stamped with the cycle they belong to), matching the chosen design's "Returned register — outstanding at the RETURNED cycle / Cycles 2" reading of a case file. Prior decision records and a recorded SLA breach are never rewritten by a resubmission; the resubmission itself is an audited event (`case_resubmitted`, old and new status, named submitter). `models.TABLES` was extended: the domain columns `cases` actually carries (`case_reference`, `risk_band`, `entity_type`, SLA fields, …) so `ext_export.py`'s TABLES-driven CSV writer does not silently drop them, plus the chat-shell/seed-data `conversations` table that the pre-existing `test_table_crud` requires (the suite was red before this slice).

  **Policy provenance.** `kyc_policy.py` transcribes the ingested corpus verbatim, not values fitted to the acceptance numbers: Risk Rating Matrix v2.1 weights (jurisdiction .30, entity structure .25, industry .20, sanctions .15, expected activity .10) and 0-100 scales, with an explicit "otherwise" default per factor; Document Checklist v2.0 including the *depth > 1* structure-chart trigger; Escalation and SLA Policy v1.4 including the full three-step chain Compliance Officer → Head of Financial Crime → COO (`kim.coo`). The matrix reproduces the slice-plan totals (55 / 51 / 76) because it is the bank's matrix, and it scores every other input correctly too.

  **Notes for later slices.** (a) *Band casing* — bands are stored and served lowercase (`"high"`), which slice 2's acceptance requires; but `workflows.json`'s `high_risk_escalation_gate` compares `evaluate_sla.risk_band` to the literal `"High"`, so slice 5's `evaluate_case_sla_status` handler must emit `kyc_policy.band_label(band)` into workflow context while still persisting lowercase. (b) *Handler ownership* — `workflow_engine.register_handler` is last-writer-wins across the sorted `ext_*.py` import order; slice 1 owns `compute_risk_score_from_matrix` and `start_sla_clock` (both real, matrix v2.1 and the business-hour clock), so slices 2 and 5 should extend `ext_cases.py`/`kyc_policy.py` rather than re-register them from a new module. (c) *Identity* — `ext_cases.acting_user(authorization, claimed)` prefers `ext_auth.current_user`; slice 4 must enforce tiers through `rbac` (kept in sync from the `users` table by `ext_cases.sync_rbac()`), never from the request body alone.
